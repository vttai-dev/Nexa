NEXA PLATFORM - API CONTRACT CHO ANTIGRAVITY FRONTEND
Cap nhat: 2026-09-28

Muc dich:
- File nay danh cho Antigravity/doc frontend de lam giao dien dung API backend.
- Tat ca endpoint API chinh dung prefix: https://localhost:7210/api/v1
- Health check KHONG dung prefix /api/v1.

QUY TAC CHUNG
1. JSON dung camelCase.
2. Enum tra ve va gui len dang string.
3. Dang nhap dung cookie first-party, KHONG dung JWT.
4. Request ghi du lieu POST/PUT/DELETE can gui CSRF:
   - Lay token: GET /api/v1/auth/csrf
   - Header can gui: X-CSRF-TOKEN: <requestToken>
   - Trinh duyet phai gui kem cookie.
5. Endpoint yeu cau dang nhap can cookie session.
6. Endpoint Admin can user co role Admin.
7. Endpoint Moderator/Admin can role Moderator hoac Admin.
8. List response dung dang:
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "totalCount": 0
}
9. Phan trang:
   - page mac dinh: 1
   - pageSize mac dinh: 20
   - pageSize toi da: 100
10. Loi tra ve application/problem+json, vi du:
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "Page must be 1–100000 and pageSize 1–100.",
  "status": 400,
  "code": "invalid_page",
  "traceId": "..."
}

1. AUTHENTICATION
======================================================================

1.1 GET /auth/csrf
Quyen: Public
Input:
- Khong co body.
Output 200:
{
  "requestToken": "CfDJ8...",
  "headerName": "X-CSRF-TOKEN"
}
Ghi chu frontend:
- Goi endpoint nay truoc moi luong POST/PUT/DELETE.
- Luu requestToken de gui header X-CSRF-TOKEN.

1.2 POST /auth/register
Quyen: Public + CSRF
Rate limit: auth
Input body:
{
  "userName": "tai_dev",
  "email": "tai@example.com",
  "password": "StrongPassword123!",
  "displayName": "Tai Dev",
  "phoneNumber": "+84901234567"
}
Validation:
- userName: 3-30 ky tu, chi a-z A-Z 0-9 _
- email: toi da 254 ky tu, dung format email
- password: 12-128 ky tu
- displayName: toi da 100 ky tu
- phoneNumber: tuy chon; neu nhap thi 8-32 ky tu, dung dinh dang so dien thoai
Output 201:
{
  "userId": "0199xxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
}
Loi thuong gap:
- 400 validation
- 409 email/username trung
- 429 rate limit

1.3 POST /auth/login
Quyen: Public + CSRF
Rate limit: auth
Input body:
{
  "email": "tai@example.com",
  "password": "StrongPassword123!"
}
Output 204:
- Khong co body.
- Backend set cookie session.
- Chi yeu cau verify neu AccountMessages:RequireVerifiedContacts=true.
Ghi chu frontend:
- Sau login nen goi lai GET /auth/csrf de lay token moi theo user da dang nhap.

1.4 POST /auth/logout
Quyen: Dang nhap + CSRF
Input:
- Khong co body.
Output 204:
- Khong co body.

1.5 Xac minh email va so dien thoai (mac dinh dang tat)
- POST /auth/email/verification { "email": "tai@example.com" }: gui lai ma email, tra 204.
- POST /auth/email/verification/confirm { "email": "tai@example.com", "token": "..." }: xac minh email, tra 204.
- POST /auth/phone/verification { "email": "tai@example.com" }: gui lai ma SMS, tra 204.
- POST /auth/phone/verification/confirm { "email": "tai@example.com", "token": "123456" }: xac minh so dien thoai, tra 204.
- API che thong tin tai khoan khong ton tai khi yeu cau gui lai ma.
- Login chi tra 403 voi code verification_required khi AccountMessages:RequireVerifiedContacts=true.
- Mac dinh khong gui mail/SMS va khong chan dang nhap; so dien thoai dang ky la tuy chon.
- Development outbox la gia lap trong bo nho, khong gui ra mang; mac dinh tat va chi bat bang AccountMessages:UseDevelopmentOutbox=true.
- Neu chua bat delivery tuong ung, endpoint gui ma tra 409 message_delivery_not_configured.
- GET /auth/dev/outbox chi duoc map khi API Development va outbox gia lap da bat; chi chap nhan loopback.

1.6 Dat lai va doi mat khau
- POST /auth/password/forgot { "email": "tai@example.com" }: yeu cau ma dat lai, tra 204 khi email delivery da bat; mac dinh tra 409 message_delivery_not_configured.
- POST /auth/password/reset { "email": "tai@example.com", "token": "...", "newPassword": "AnotherStrongPassword123!" }: dat lai mat khau, tra 204.
- PUT /me/password { "currentPassword": "...", "newPassword": "..." }: doi mat khau khi da dang nhap, tra 204.
- Chua ket noi Gmail/business email hoac nha cung cap SMS cu the. Khi co provider, cau hinh webhook HTTPS, bat EnableEmailDelivery/EnablePhoneDelivery va RequireVerifiedContacts trong AccountMessages; frontend bat NEXT_PUBLIC_ACCOUNT_VERIFICATION_ENABLED=true.
- Khi bat RequireVerifiedContacts, API dung khi thieu provider email hoac SMS; co the dung outbox gia lap chi de test local.
